\section{Precedents for Re-execution}
\label{sec:reexecution-precedents}

The \code{repro} manifest, \code{repro.yaml}, lists each command to rerun, the input files the
command reads, and the numbers the manuscript prints from its output. \code{repro reproduce}
reruns each listed command in a directory that holds only that command's declared inputs, and
then compares every number the manuscript prints from the output with the value at its declared
address. Table~\ref{tab:reexecution-precedents} sets each
of its design choices beside the closest earlier system and states the difference. Most choices
have a direct precedent. Three do not, in the sources read: an outcome for a rerun whose number
could not be read, a label on a step that ran after an upstream failure, and a comparison of a
printed value with a declared address in an output file that stays with the project.

\paragraph{Chain-of-Evidence.} ScientistOne \citep{meng2026scientistone} is an autonomous
research system whose writer tags each sentence that holds a number with a line of its
experiment log, and whose audit reruns submitted code and compares the result with the reported
score. \code{repro reproduce} differs from it in five ways. (1)~\emph{Who can use it.} The
tags exist only for papers that ScientistOne itself writes, and its audit needs a benchmark's
own evaluator; the \code{repro} manifest is written for any project, by a person or an agent, and
lists the author's own commands. (2)~\emph{What the reader receives.} ScientistOne removes the tags from
the final manuscript; the manifest, the pinned inputs and the log of reruns stay in the
repository, so a reader repeats the check from a clone. (3)~\emph{How a check is decided.} Its
audit has a language model read the reported score out of the paper, and two of its four checks
are majority votes of a language model; every claim in the manifest is machine-checkable, in
that the number the manuscript prints is compared, as a decimal at the precision printed, with
the value at its declared address in the rerun output, and no language model takes part. (4)~\emph{What is fixed beforehand.} A regeneration
runs only on inputs whose bytes match their pins, and a changed input is reported as
\code{not re-run}; the ScientistOne paper describes no digest of an input or an output. (5)~\emph{What a result can be.}
Its numeric check passes or fails, and its authors sort the misread values by hand;
\code{unchecked}, \code{failed} and \code{not re-run} are outcomes of their own, so a check that
could not be made is never counted with those that passed. ScientistTwo applies the same audit
to its own output and reports every score verified on 49 target problems
\citep{nam2026scientisttwo}. Its coding agent audits the repository against the manuscript, the
rerun in the one audit report the paper reproduces covers the proposed method and not the
baseline, and the paper states no tolerance for a score to count as verified.

\paragraph{Reproduction by an agent.} SEER-Repro has a coding agent re-derive 2{,}190 atomic claims
of 20 published cancer-registry papers from the registry data, and reproduces 77.4\% of them
\citep{liu2026seerrepro}. A language model extracts each reproduced value from the agent's
report, and deterministic code then applies the tolerance. The two designs start from opposite
ends. In SEER-Repro a model extracts the claims from a published paper, the reference is the
published number, and the analysis is rewritten by the agent; in the \code{repro} manifest the
author declares each claim and its address, the reference is the project's own output, and the
command that is rerun is the author's.

\paragraph{Checklists and badges.} The machine learning reproducibility checklist asks an author
to state what a paper includes \citep{pineau2020improving}, and an ACM badge records that
the main results were obtained in a later study by a team other than the authors
\citep{acm2020badging}. Neither specifies what is rerun or
compares a printed number with an output. The \code{repro} manifest states what is rerun, as a
list of commands and the input files each reads, and the log of \code{repro reproduce} records
for every printed number whether the rerun output still holds it.
